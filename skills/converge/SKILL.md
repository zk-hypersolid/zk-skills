# 收敛

评审找到漏洞就补一条，写一句几乎免费，删一条没人看见。本 skill 用在要做一整轮减法时：让「删」是默认动作，「加」承担举证。姿态规则（阶段、常见/罕见、净变化、何时停）在全局 CLAUDE.md「阶段与收敛」，这里只写做法。

## 步骤

1. **量现状。** 按 CLAUDE.md 确认阶段和完成标准（没有就先问用户）。数条数、字数、功能项，和上一版比，只作参考。
2. **逐条过筛子。** 对每一条问两件事：不写它，执行方按常识或行业现成做法会做错吗？做错了可逆吗？
   - 会错且不可逆 → 留，压成一句底线。
   - 会错且可逆、情形常见 → 留。
   - 会错且可逆、情形罕见 → 不写规则，写进不保证 / 监控 / 事后处理。
   - 不会错 → 删（它在复述常识或行业默认）。
   - 判断不了（例如常见还是罕见说不准、两个方向的后果不同、和别的条款冲突）→ 不替人拍板。答案会改变意思、范围或风险的，写成一个问题进待决，附推荐和什么证据能定下它；不会的，按可逆的方式先处理并标出来。
3. **过了筛子的压到最小形态。** 文档只写结果一句；做法、边界情形、检查清单交给执行方，落成测试，不落成条文。
4. **交付。** 分四类：保留（改写）/ 删除 / 移出正文（交给执行方做成测试，或写进不保证、监控、事后处理）/ 待决（问题、推荐、依据）；写明 +n / −m 和净变化。净增按来源分成真实产出和补丁；每条补丁要过筛子并说出换掉了哪一条，说不出来的进「以后再看」清单。converge 改的是语义，属 doc-writing 里「要用户授权」的一类：语义上的删除先交 owner，确认后再改正文；只删重复的不用。约束本身对不对用 /premise-challenge 判断；约束定下后做法先抄现成的，这里不重推约束。

派评审 agent 时按 `agent-brief` 写 brief。

## 常见失败
- 删掉承重的定义：删前查别的条款是否引用它。
- 用「更短」代替「更对」：删的是复述常识和罕见情形的条文，不是条件和否定。
